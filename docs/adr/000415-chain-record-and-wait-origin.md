# 連鎖の記録は進めた Issue ごとに足すコメントにし、待つ時間は PR の作成時刻から数える

## 背景と課題

[ADR 000411](000411-unattended-merge-and-chain-guardrails.md) は、連鎖の件数を「連鎖の最初の Issue に付けるコメント（連鎖の id と、これまでに進めた Issue の番号の一覧）」に残すことと、PR がマージされるまで待つ時間（`auto.chain.wait_minutes`）を決めている。task-auto-sequence スキル（#415）を実装するとき、次の2点が、そのままでは実装できなかった。

* 一覧を持つ1つのコメントは、進めるたびに書き換える必要がある。書き換えには `gh api` での編集が要り、同じ連鎖の実行が重なると、足した分が消えるおそれがある。
* 待つ時間は、ADR では「PR を出して task-auto が終わった時刻」から数えるが、その時刻を後から取る手段が無い。

この2点について、ADR 000411 のどこを変えるかを決める。それ以外（件数の上限・止める手段・止まる条件・次の Issue の選び方）は ADR 000411 のままにする。

## 判断の決め手

* 並行して実行しても、足した記録が消えないこと
* 同じ Issue を足し直しても、件数が増えないこと
* ADR 000411 の「最初の Issue のコメントから数え、読めなければ連鎖を終える」「次の Issue に進む前に先に記録する」を守れること
* 起点の時刻を、後から確実に取れること

## 検討した案

* ADR 000411 のとおり、1つのコメントに一覧を書き、進めるたびに書き換える。待つ時間は、task-auto が終わった時刻から数える
* 進めた Issue ごとに1件のコメントを足す。待つ時間は、PR の作成時刻から数える

## 判断の結果

選んだ案：「進めた Issue ごとに1件のコメントを足す。待つ時間は、PR の作成時刻から数える」。理由は、コメントを書き換えずに足すだけにすれば、並行実行でも記録が消えず、同じ Issue を足し直しても重複を1件と数えられるから。task-auto が終わった時刻は後から取れないが、PR の作成時刻（`createdAt`）は常に取れるから。

記録の形：

* 連鎖の最初の Issue に、進めた Issue ごとに1件のコメントを足す。コメントの先頭は `<!-- dev-workflow:task-auto-sequence chain=<連鎖の id> issue=<Issue の番号> -->` の印にする。
* 件数は、同じ連鎖の id の印に書かれた Issue の番号の数（重複は1件）で数える。先頭が印のコメントだけを数え、コメントの作者は確かめない。
* 足す前に、足す Issue を読んで確かめる（PR の番号・無い番号なら足さずに止まる）。

待つ時間：

* PR が OPEN のあいだ、PR の作成時刻から `auto.chain.wait_minutes`（既定 120 分）が過ぎるまでは、何も書き込まずに終えて待つ。過ぎたら、連鎖を終える。

### 結果として起きること

* 良い点：並行実行でも足した記録が消えない。再実行しても件数が増えない。
* 良い点：起点の時刻が常に取れる。
* 悪い点：連鎖の最初の Issue のコメントが、進めた件数だけ増える（上限の既定は 3）。
* 悪い点：PR の作成から CI やレビューに長い時間がかかると、その分も待つ時間に数えられ、連鎖が早く終わることがある。
* 悪い点：印で始まるコメントをだれが書いても数えるので、書き込める人が件数を増減できる。

### 確認

`tests/chain-record.bats`（足す・数える・重複を1件と数える・読めなければ止まる）と `tests/chain-decide.bats`（待つ・待つ時間が過ぎて終える）で確かめる。

## 補足

この ADR は、[ADR 000411](000411-unattended-merge-and-chain-guardrails.md) の「連鎖の歯止め」のうち、件数を残すコメントの形（1つのコメントの一覧を、進めた Issue ごとのコメントにする）と、`auto.chain.wait_minutes` を数え始める時刻（task-auto が終わった時刻を、PR の作成時刻にする）だけを変える。それ以外の決めたことは、ADR 000411 のままである。ADR 000411 の本文は書き換えない。
